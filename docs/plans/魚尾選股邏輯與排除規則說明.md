# 魚尾選股邏輯與排除規則完整說明（2026-07-22）

> 對應程式碼版本：Phase 2 production cutover 之後（`SIGNALS_PIPELINE_MODE` 預設 `phase2`）。
> 本文件目的：把「哪幾檔進來 → 哪幾檔活到哪一關 → 最後誰被 LLM 選中」的完整規則
> 一次講清楚，含目前正在跑的 Phase 2 路徑，以及仍照跑當 fail-safe 的 legacy 路徑。

---

## 0. 現在誰在真正決定選股結果？

`app/signals/pipeline.py` 靠環境變數 `SIGNALS_PIPELINE_MODE` 決定：

| 模式 | 行為 |
|------|------|
| `legacy` | 完全走本文件「路徑 A（legacy）」，Phase 2 模組零執行 |
| `phase2_shadow` | 真正輸出仍走路徑 A，但額外跑一次路徑 B（Phase 2）存進 `signal_shadow_snapshots` 做比對 |
| **`phase2`（目前 production 預設值）** | **真正輸出走路徑 B（Phase 2）**；路徑 A 仍照跑，只當 fail-safe（Phase 2 出例外時退回）與監控基準 |

**簡單說：現在你在首頁看到的魚尾清單，是路徑 B（Phase 2）產生的。** 路徑 A（legacy）沒有被刪除，只是退居備援與對照角色。

兩條路徑**共用同一個候選池建立階段**（下面 Step 1），只有候選池建好之後「怎麼判斷角色、怎麼決定活下來」不同。

## Step 1：候選池怎麼進來（兩條路徑共用，`app/signals/candidate_pool.py`）

### 1.1 資料窗口（`ingest_data`）
抓最近 60 個交易日的 `daily_price` + 全部 `is_active=True` 的股票基本資料，切出 2 日 / 3 日 / 5 日 / 10 日 / 60 日五種窗口供後面各項指標使用。

### 1.2 產業排行（`compute_rankings`，排序窗 = 2 個交易日）
1. 全市場各產業依「近 2 日三大法人合計淨買超」排序
2. 由高到低取，**遇到金融類產業直接跳過（順延，不佔名額）**，湊滿 **10 個非金融產業**
3. 另外單獨算「當日（1 日）」各產業淨額，取最賣超的前 **10 個產業**列為「當日賣超黑名單」
4. 前面選出的 10 個產業中，若落在當日賣超黑名單 → **剔除，不回補**（剩幾個算幾個）

### 1.3 個股排行
用既有 M22 熱錢服務（`hot_money_service.compute_hot_money`），近 **2 日**三大法人合計淨買超前 **30 大個股**。

### 1.4 候選池組成（四通道聯集，`build_candidate_pool`）
候選池是以下來源的**聯集**（同一檔股票可能同時符合多個通道）：

- **A. 法人資金通道**：
  - 個股熱錢前 30 大（上面 1.3）
  - 10 個入選產業的**全部成分股**
  - 個股熱錢前 6 大所屬**集團**的**全部成員**（`group_stocks.json`，目前 5 大集團：鴻海／台塑／國巨／聯電／聯發科）
- **B. 價格動能通道**（`momentum.py` 全市場動能 frame 計算，任一成立）：
  - 全市場相對強度百分位（`rs_market_percentile_20d`）**≥ 85**
  - 或產業內相對強度百分位（`rs_industry_percentile_20d`）**≥ 80**
  - 或收盤創 **20 日新高**（`distance_to_20d_high ≥ 0`）且當日量 ≥ 20 日均量 **1.2 倍**
  - 或 60 日報酬百分位達標且近 5 日報酬為正
  - 依 RS 排名取前 **40 檔**
- **C. 動能加速通道**：近 5 日相對強度排名進步 **≥ 200 名**，且全市場 RS 百分位 **≥ 70**；取前 **20 檔**
- **D. 基本面動能通道**（月營收，`available_date` = 次月 10 日，無資料穿越）：
  - 月營收 YoY **> 15%** 且連兩月加速，或 YoY 由負轉正，或產業內 YoY 百分位 **≥ 80**；取前 **20 檔**

**排除**：ETF（代號 `00xxx`）、金融股（industry 含「金融/銀行/保險/證券」）、人工黑名單（目前為空）、不在 `stocks_master` 的股票。

**每檔候選會 merge**：完整動能特徵（momentum_score 及子分數、RS 百分位、量比、法人資金 1/3/5 日、融資融券張數與變動、產業內排名等）+ **再偵測閘門追蹤狀態**（見下方 1.5）。

**截斷**：候選池超過 **150 檔**才觸發截斷，依 `momentum_score` 排序只留前 **120 檔**（正常情況很少觸發）。

### 1.5 再偵測閘門（追蹤狀態，兩條路徑共用資料）
對「已被抓過、仍在 30 日追蹤窗內」的股票，額外算：
- `first_seen_date` / `hit_count` / `days_since_first_seen`
- `max_positive_return_pct` / `max_negative_return_pct`（自首次抓到後累計極值）
- `consecutive_hit_count` / `independent_hit_count`（同一波段 vs 不同波段）
- **`failed_follow_through`**：`days_since_first_seen ≥ 3` 且 `max_positive_return_pct < 3%` 且 `max_negative_return_pct < -6%` → 判定「主升段驗證失敗」，這面旗標會在後面的 hard exclusion 直接剔除，不再進新的候選名單

## Step 2A：Legacy 路徑（`classification.py` + `filters.py`）— 現在只當 fail-safe / 監控基準

### 2A.1 三選一預分類（`classification.classify_stocks`）
不符合任何一類 → **直接剔除**（legacy 的硬傷，Phase 2 就是為了解決這個「非黑即白」設計）。

**LEADER**（六條件**全部**滿足）：
1. 產業 20 日相對強度全市場前 30%（`industry_rs_percentile_20d ≥ 70`）
2. 個股產業內相對強度前 20%（`rs_industry_percentile_20d ≥ 80`）
3. `momentum_score ≥ 70`
4. 近 3 日至少 2 日法人買超，或法人買超佔成交值百分位前 20%
5. `volume_5d_to_60d_ratio ≥ 1.3`
6. 距 20 日高點不超過 3%（`distance_to_20d_high ≥ -3%`）

**FOLLOWER**（五條件全部滿足）：同產業有 LEADER + `55 ≤ momentum_score < 70` + 近 5 日漲幅低於該產業 LEADER + RS 排名改善中 + 近 3 日法人淨買超為正 + 無爆量長上影。

**ROTATION_LAGGARD**（七條件全部滿足）：同產業有 LEADER + 產業仍強（`industry_rs_percentile_20d ≥ 70` 或近 3 日入榜前 10 產業）+ 20 日報酬落後產業平均 ≥ 5 個百分點 + RS 排名改善中 + （法人由賣轉買 或 量能轉強 `>1.2x`）+ （站回 10 日均線 或 突破創 20 日新高）+ `momentum_score ≥ 50`。

### 2A.2 Legacy Hard Exclusions（`filters.apply_hard_exclusions`，任一命中即剔除）
1. ETF / 金融股 / 黑名單
2. 三大法人合計近 5 日淨額 **< 0** 且該股**不是** ROTATION_LAGGARD（LAGGARD 本身允許法人偏負）
3. 近 3 日漲幅 **> 15%**（過熱防追高）
4. 5 日均成交金額 **< 5,000 萬 TWD**（流動性不足）
5. 當日成交量未達股價級距門檻（見下方「共用規則」）
6. `failed_follow_through`（再偵測閘門）
7. 近 10 日漲幅 **> 25%** 且當日法人轉賣（`total_institution_flow_1d < 0`，派發前兆）
8. 近 3 日法人累積買超為正但當日反轉大賣，且當日跌幅 **< -1.5%**（主力出貨確認）
9.（v2.1）全市場 RS 百分位 **< 40** 且近 5 日排名未改善（`rs_rank_improvement_5d ≤ 0`）→ 動能死水

### 2A.3 Legacy Soft Filters（標 hint，不剔除；`filters.apply_soft_filters`）
- `weakening`：近 3 日法人買超為正，但當日賣超 > 3 日累計的一半
- `retail_overheated`：融資 3 日變動 **> +5%** 且法人 3 日淨額 ≤ 0
- `distribution`：爆量不漲（當日量 > 60 日均量 2 倍且當日收黑）**或** 高檔長上影（上影線 > 實體 2 倍且收盤 < 當日高點 97%）
- `range_bound`：近 10 日高低差 **< 5%**

### 2A.4 Legacy Regime Gate（`filters.apply_regime_gate`，依大盤狀態收斂）
見下方「Market Regime 判定」+「Regime Gate 對照表」。

## Step 2B：Phase 2 路徑（`app/signals/phase2/`）— **目前真正驅動 production 的路徑**

Phase 2 **完全沿用 Step 1 的候選池**，不重新定義候選池怎麼來。差異在候選池建好之後：

### 2B.1 定義性 Hard Exclusion（`pipeline_v2.build_phase2_pool` → `regime_gate.is_true_hard_exclusion`）
Phase 2 的第一道關卡比 legacy 更早、更寬鬆（**故意不含** legacy 條件 #2「法人 5 日淨額轉負」，因為那條依賴 legacy 的三選一分類）：

1. ETF / 金融股 / 黑名單
2. `failed_follow_through`
3. `entry_state == STRUCTURE_DAMAGED`（結構性破壞，見下方 entry_state 定義）
4. `risk_gate_action == EXCLUDE`（deterministic_signals 算出，見下方）
5. 近 3 日漲幅 **> 15%**（過熱，沿用 legacy 同一常數）
6. 5 日均成交金額 **< 5,000 萬 TWD**（流動性不足，沿用 legacy 同一常數）
7. 當日成交量未達股價級距門檻（見下方「共用規則」）
8. 近 10 日漲幅 **> 25%** 且當日法人轉賣（沿用 legacy 同一常數）
9. 近 3 日法人買超為正但當日反轉大賣 + 當日跌幅 **< -1.5%**（沿用 legacy 同一常數）

> **`distribution` 這個 soft hint 不在這裡**（2026-07-21 起降級為僅影響信心度，見下方 conviction）——大盤系統性下跌日這個訊號雜訊很大，容易誤殺長上影的強勢股，兩邊（legacy 的 soft filter、Phase 2 的 hard exclusion）都刻意不讓它變成硬剔除條件。

### 2B.2 Sector Context（`sector_context.py`）— 產業從「硬條件」變成「描述環境」
- 階層式 peer scope：`SUB_SECTOR → PRIMARY_SECTOR → MARKET_ONLY`，樣本數 **< 5 檔**就自動退到上一層（避免「這產業只有 1 檔股票」硬生出 100 percentile 假訊號）
- 拆成兩個獨立指標：`sector_strength_percentile_20d`（整個產業強不強，跟其他產業比）與 `peer_rs_percentile_20d`（這檔股票在自己同儕裡強不強），不再共用一個模糊的「產業 RS」
- `sector_context_quality`：來自 Phase 1 canonical 分類的信心度（HIGH/MEDIUM 可用；LOW 不可用於硬分組，會自動走 MARKET_ONLY）

### 2B.3 Entry State（`entry_state.py`）— 與角色判定完全分離
用「距高點回落幅度 ÷ 14 日 ATR」取代舊版死板的「距 20 日高點 -3%」門檻：
- `NEAR_HIGH` / `NORMAL_PULLBACK` / `DEEP_PULLBACK` / `REACCELERATING` / `STRUCTURE_DAMAGED`

### 2B.4 New Discovery vs Tracked 分流（`tracking_state.py`）
**已被抓過、仍在 30 日追蹤窗內**的股票，**不重新參加角色選秀**，改問「原本的強勢邏輯還在嗎」：

- `ACTIVE_TREND`：一切正常
- `HEALTHY_PULLBACK`：正常/深度回檔但 `max_negative_return_pct > -15%`
- `REACCELERATING`：entry_state 為 REACCELERATING
- `DETERIORATING`：動能轉弱（`momentum_phase == "weakening"`）、結構破壞、或 RS 排名嚴重惡化中的回檔
- `INVALIDATED`：`failed_follow_through` 命中

**新股（未被追蹤過）** 才會走下面的角色分類。

### 2B.5 Sector Momentum Cluster（`sector_cluster.py`）
讓 FOLLOWER 資格不必依賴「這個產業一定要有一檔完美 LEADER」——整個產業的強度／法人流向／強勢股數量達標，也能打開 FOLLOWER 路徑（解決航運類股沒有 formal LEADER 就全滅的問題）：`ACTIVE` / `NEUTRAL` / `COOLING` / `FAILED` / `UNAVAILABLE`。

### 2B.6 Base Momentum Eligibility（`roles.is_base_momentum_eligible`）
比 legacy 寬鬆很多，只濾掉明確弱勢股：`momentum_score ≥ 50` 且 `rs_market_percentile_20d ≥ 40` 且 `momentum_phase != "weakening"`。**注意：這裡不檢查 `distribution`**（跟 hard exclusion 一致，避免兩個入口互相打架）。

### 2B.7 角色分類（`roles.classify_roles`）— evidence-count，不是 6-way AND
**六項證據**（sector 強度達標 / 個股產業內 RS 達標 / momentum_score 達標 / 法人確認 / 量能確認 / 價格結構完整），**用計數而非「必須全滿足」**：

- **SECTOR_LEADER**：sector context 可用 + 證據數 **≥ 5**
- **CO_LEADER**：sector context 可用 + 證據數 **≥ 4**
- **INDEPENDENT_LEADER**：sector context 不可用或不夠強，但個股 `rs_market_percentile_20d ≥ 90` + `momentum_score ≥ 75` + 非 sector 相關證據數 **≥ 3**（解決漢翔這種單一樣本產業的股票）
- **SECTOR_FOLLOWER**：同產業有 formal leader 或 sector cluster = ACTIVE + `40 ≤ momentum_score < 70` + RS 排名沒有惡化
- **ROTATION_LAGGARD**：follower 資格成立 + 產業強（`sector_strength_percentile_20d ≥ 70`）+ 個股相對落後（`peer_rs_percentile_20d < 50`）+ RS 排名改善中
- **EMERGING_MOMENTUM**：RS 排名快速改善（`≥ 30 名`）且 `momentum_score ≥ 45`（尚未確立地位但正在被重新定價）
- **UNCLASSIFIED_MOMENTUM**：符合基本資格但三類角色都不符 → **不等於死亡**，繼續往下走 risk/regime（這是 Phase 2 跟 legacy 最大的差別：legacy 這裡直接刪掉）

`base_eligible = False` 的股票才會真正被剔除（不進 `eligible_candidates`）。

## Market Regime 判定（`market_regime.py`，兩條路徑共用，backend deterministic，LLM 不可覆寫）

用 `daily_price` 裡的 TAIEX 指數 OHLC 歷史（近 65 個交易日）算：

**優先序**：`RISK_OFF` > 高波動 `VOLATILE_RANGE`（overlay）> `BULL_TREND` > 其餘 `VOLATILE_RANGE`

1. **RISK_OFF**：收盤跌破 MA20，且（MA10 也在 MA20 下方 **或** 近 5 日跌幅 ≤ -3%）
2. **高波動 VOLATILE_RANGE（關鍵 overlay）**：即使指數創高，只要下列任一成立就視為震盪盤：
   - 近 5 日平均盤中振幅（(高-低)/收盤）**≥ 2.8%**
   - 近 5 日出現 ≥ 1 次「創高急殺」（收盤距當日高點 ≤ -2% 且當日收黑 ≤ -1%）
   - 近 3 日內任一日跌幅 **≤ -2.5%**
3. **BULL_TREND**：收盤 ≥ MA10 ≥ MA20，MA20 近 5 日上揚，近 10 日報酬為正，且波動可控（沒觸發第 2 點）
4. 其餘 → `VOLATILE_RANGE`

資料不足（< 20 筆）→ 保守視為 `VOLATILE_RANGE`。

**市場廣度疊加（`market_breadth.py`，只影響 legacy 路徑的 deterministic gate，不影響 LLM 契約的 3 態）**：`BULL_TREND` 再依全市場站上 MA20 比例、漲跌家數比、創新高低家數、強勢產業比例算出 0~100 的 `breadth_score`；`< 50` → 細分為 `NARROW_BULL`（指數強但個股弱，少數權值股撐盤，要加嚴）。

## Regime Gate 對照（活下來的最後一關，決定進 LLM 前的名單）

| Regime | Legacy（`filters.apply_regime_gate`） | Phase 2（`regime_gate.apply_regime_gate_v2`） |
|---|---|---|
| **BULL_TREND / BROAD_BULL** | `momentum_score < 50` 剔除 | 不額外剔除（只做 hard exclusion） |
| **BULL_TREND / NARROW_BULL** | 只留（LEADER 且 `score≥65`）或（`score≥70` 且無 distribution） | 同左（Phase 2 沒有廣度細分，維持一般規則） |
| **VOLATILE_RANGE** | 剔除：有 `distribution` hint／急拉突破（當日量>5日均量2倍 且 當日漲>5%）／`momentum_score<60`／RS 排名 5 日惡化 ≥50 名／conviction=low 且非（已追蹤且表現尚可） | 不額外剔除（Phase 2 靠 conviction 分級，不在這關直接刪） |
| **RISK_OFF** | 只留：LEADER + `hit_count≥3` + 近 5 日法人為正 + 非 distribution | 只留：（`role` 是 formal leader **或** `tracking_state` 是 ACTIVE_TREND/REACCELERATING/HEALTHY_PULLBACK）+ `rs_market_percentile_20d ≥ 90` |

**Conviction（信心度 high/medium/low，兩邊都有但算法不同）**：
- Legacy：依 regime 各自的 `hit_count` / `momentum_score` / `is_leader` 組合判斷，資料導向校準（震盪盤 `hit_count≥3` → high，單次命中非 LEADER → low）
- Phase 2：`hit_count` **完全不再是任何 regime 的 hard gate**，只在這裡影響 conviction；`distribution` hint 命中 → conviction 降一級（high→medium→low→low）

## 共用規則（兩條路徑都會用到的門檻常數）

- **過熱防追高**：近 3 日漲幅 > 15% → 剔除
- **流動性門檻**：5 日均成交金額 < 5,000 萬 TWD → 剔除
- **當日成交量死線**（依股價級距）：
  - 股價 < 1000 元 → 日量需 > **1500 張**
  - 1000 ~ 5000 元 → 日量需 > **800 張**
  - ≥ 5000 元 → 日量需 > **500 張**
- **派發前兆**：近 10 日漲幅 > 25% 且當日法人轉賣 → 剔除
- **出貨確認**：3 日累積買超但當日反轉大賣 + 當日跌幅 < -1.5% → 剔除

## Deterministic Signals（`deterministic_signals.py`，給 LLM 的既定判讀，不可改寫）

在 hard/soft filter 之後、送進 LLM 之前，每檔候選會被算出以下欄位（LLM 只能照填，不能自己判斷）：

- `chip_trend`：weakening（法人急轉賣）> retail_overheated（散戶過熱）> short_squeeze_potential（資減券增+股價未跌）> accumulating（連買 2 日+量增）> neutral
- `technical_status`：distribution（出貨型態）> breakout（創高）> steady_uptrend（站穩 MA20 上升）> early_turn（站回 MA10+RS 改善）> range_bound（盤整）> weak
- `entry_quality`：extended_chase（急拉追高危險）> breakout_confirmed（突破有承接）> pullback_setup（回測再啟動）> failed_rotation（產業輪動失敗）> neutral
- `sector_rotation_status`：inflow（產業 3 日+1 日都買超）/ cooling（3 日買超但當日轉弱）/ failed_rotation（產業弱且個股 RS 不足）/ neutral
- `institution_flow_momentum`：reversal（3 日買超但當日轉賣）/ accelerating（當日買超遠高於均值）/ decelerating（當日買超遠低於均值）/ stable / neutral
- `risk_gate_action`：**EXCLUDE**（出貨+法人反轉，或輪動失敗+動能轉弱 → 結構性風險）／**MAX_B**（散戶過熱/急拉追高，可觀察但不可積極）／**DOWNGRADE_ONE_LEVEL**（其他任一風險旗標）／**PASS**

`risk_gate_action == EXCLUDE` 這條同時也是 Phase 2 hard exclusion 的條件之一（見 2B.1 第 4 點）。

## LLM 相容層（Phase 2 → 既有 LLM 契約，2026-07-22 新增）

Phase 2 的角色（SECTOR_LEADER / CO_LEADER / INDEPENDENT_LEADER / SECTOR_FOLLOWER / ROTATION_LAGGARD / EMERGING_MOMENTUM / UNCLASSIFIED_MOMENTUM / 已追蹤股的 tracking_state）需要映射回既有 LLM prompt 認得的三分類（`pipeline_v2.role_to_prelim_type`）：

| Phase 2 角色 | 映射到 |
|---|---|
| SECTOR_LEADER / CO_LEADER / INDEPENDENT_LEADER | LEADER |
| SECTOR_FOLLOWER | FOLLOWER |
| ROTATION_LAGGARD | ROTATION_LAGGARD（沿用既有邏輯再轉 LAGGARD） |
| EMERGING_MOMENTUM | FOLLOWER |
| UNCLASSIFIED_MOMENTUM | LAGGARD |
| 已追蹤股：ACTIVE_TREND / REACCELERATING | LEADER |
| 已追蹤股：HEALTHY_PULLBACK | FOLLOWER |
| 已追蹤股：DETERIORATING / INVALIDATED | LAGGARD |

這是工程判斷（非 spec 硬性規定），目的是讓既有 v1/v4/v5 prompt 不需要重寫就能吃 Phase 2 輸出。LLM 看到的 `type` 是映射後的值，**不可自己改判**；額外會看到 `phase2_role` / `phase2_tracking_state` / `phase2_entry_state` 三個欄位，作為 reason 引用具體狀態的依據。

**送進 LLM 前還有一道上限**：`LLM_INPUT_HARD_LIMIT = 50`，超過就依 `prelim_type` 優先序（LEADER > FOLLOWER > ROTATION_LAGGARD）+ 法人金額排序截斷。

## LLM 決策層（`llm_caller.py`，deterministic 決定完之後才輪到 LLM）

目前所有大盤狀態（regime）都預設走 **v5 prompt**（`watch-list-stock-v5.md`；「相對強度動能」版本，v1/v4 保留給人工重跑對照，可用 env `SIGNALS_FORCE_PROMPT_VERSION` 強制指定）。

1. **STEP 0（market context）**：只查外部風險背景（VIX / 美股 / 台指期 / USD-TWD），**盤勢判斷完全交給 backend**（`market_regime` 由上面 market_regime.py 算好，LLM 不可覆寫）
2. **STEP 2-4（research，8 檔一批）**：上網查公司業務、產業鏈位置、題材延續性、集團/龍頭股表現；`type` 照抄 backend 給的值，不可重判
3. **STEP 5-9（decision，4 檔一批）**：依 momentum gate → regime gate → risk cap → 題材驗證的順序，先對全部候選給 WATCH / REMOVE 短判斷
4. **補長理由**：只對 WATCH 名單額外跑一次，產出 500-1000 字的中文理由（含大盤融資融券解讀 `margin_analysis`）
5. **組裝**（`assemble_final_output`）：拆 watchlist / removed，蓋回 deterministic 的 `conviction` / `watch_intensity` / `regime` / `signal_metrics`（LLM 給的這幾欄會被後端覆寫，不採信）

## 整條 Pipeline 總覽（`pipeline.py::run_signal_pipeline_sync`）

```
ingest_data → compute_rankings → build_candidate_pool（Step 1，兩路徑共用）
        │
        ├─ 【Legacy 分支】classify_stocks（三選一硬刪除）
        │       → apply_hard_exclusions → apply_soft_filters
        │       → attach_deterministic_signals → apply_regime_gate
        │       → after_regime_legacy
        │
        └─ 【Phase 2 分支】build_phase2_pool（定義性 hard exclusion）
                → run_phase2_pipeline（sector_context → entry_state →
                  tracking_state 分流 → sector_cluster → role 分類 →
                  apply_regime_gate_v2）
                → after_regime_phase2（+ role_to_prelim_type 映射）

若 SIGNALS_PIPELINE_MODE == "phase2"：
    after_regime = after_regime_phase2（capped 50 檔）  ← 目前正式用這個
    Phase 2 例外 → fail-safe 退回 after_regime_legacy
否則（legacy / phase2_shadow）：
    after_regime = after_regime_legacy                  ← 真正輸出
    （phase2_shadow 模式下，Phase 2 額外跑一次存 shadow snapshot）

        ↓
assemble_market_context（STEP 0）
        ↓
run_research_batch（STEP 2-4，8 檔/批）
        ↓
run_explanation_batch（STEP 5-9 短判斷，4 檔/批）
        ↓
run_watch_reason_batch（只對 WATCH 名單，補長理由）
        ↓
assemble_final_output → 蓋回 deterministic conviction/watch_intensity/signal_metrics
        ↓
寫入 signal_snapshots（首頁看到的）+ signal_watch_hits（30 日追蹤）
        ↓
（無論哪個分支）signal_shadow_snapshots 都會記錄 legacy vs phase2 兩邊的存活名單比較
```

## 想查「某天某檔股票走到哪一關」怎麼看

1. **前端**：`/signals/archive`（30 日追蹤頁）header 右上角小灰字連結「Phase 2 Debug View →」進 `/signals/phase2`，可選日期、看候選池/存活數統計、角色分布、每檔可展開的完整決策路徑（含被剔除的原因）
2. **API**：`GET /api/signals/phase2/shadow-dates`（有紀錄的日期）、`GET /api/signals/phase2/shadow/{date}`（單日完整內容）
3. **DB 表**：`signal_shadow_snapshots`（`funnel_metrics` / `explain_traces` / `comparison_summary`）
4. **手動重跑單一日期查特定股票**（backend 目錄）：
   ```bash
   python run_phase2_replay.py 2026-07-14 --stocks 8039
   ```
   會直接印出該股票「連候選池都沒進來」／「進了候選池但被 Phase 2 hard exclusion 剔除（含原因）」／完整 explain trace 三種結果之一。
