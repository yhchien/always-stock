## 0. 先講最重要的現況

目前預設設定是：

| 設定 | code 預設 | 實際影響 |
|---|---|---|
| `SIGNALS_PIPELINE_MODE` | `phase2` | Phase 2 存活者取代 legacy，成為真正送入 LLM 的候選 |
| `WATCH_QUALITY_MODE` | `shadow` | 會計算 freshness / READY / SETUP / RESERVE，但 **RESERVE 仍送 LLM** |
| `SIGNALS_MOMENTUM_SCORE_MODE` | `applicability_aware` | ETF 公司基本面為 N/A、排除該權重後正規化；一般股/金融股缺資料仍是 0 分 |
| `SIGNALS_MOMENTUM_SCORE_AVAILABLE_WEIGHT` | `false` | 只在 `legacy` replay mode 控制歷史 missing-normalization 行為 |
| Candidate total cap | disabled | Raw union 與 Phase 2 LLM input 全部保留，只做 deterministic ordering |
| Prompt family | `v7` | 單一共用政策加六階段獨立契約；LLM 不可重跑第二套選股 gate |
| Global selection | `v7_global_selector` | 所有研究成功且無真實 veto 的候選一次全體比較；無 Top-K/ratio/quota |
| Tracking prompt | `v7_tracking` | 只驗證截至 review date 的外部 thesis，不決定 lifecycle |
| Tracking state machine | `p4_state_v1` | Backend 每日決定 CONTINUE/CAUTION/STOP；技術失敗獨立 |

三個容易混淆的數量控制：

1. B/C/D 通道各自最多 40/20/20 檔。
2. raw union 依 momentum score 排序，但不做總量截斷。
3. Phase 2 全部 gate 完成後，所有 `llm_eligible` 都送入 LLM batches。

Prompt v7 Research 預設 batch size 4、Assessment batch size 4，只是工程分批，不是
選股上限。Research 使用 Structured Outputs；若整批仍發生格式／契約失敗，會二分重試
直到隔離至單檔，單檔再依自己的拒絕原因修正一次，避免一份壞 JSON 讓整批候選全部
失敗。若修正後仍夾帶分析日之後的來源，Backend 會丟棄整份受污染的研究敘事，改成
`UNCONFIRMED`／LOW confidence 的中性紀錄；不讓未來資訊進入 Assessment，也不把資料
未確認冒充 `REMOVE`。Legacy replay 的 Research batch size 仍為 8。Global selector
不分批，必須一次處理全部 compact cards；語意契約失敗時至多重送一次完整集合，不做
局部修補或 tournament。

## 1. Production 呼叫鏈

入口：`backend/app/signals/pipeline.py::run_signal_pipeline_sync`

```text
ingest_data
  → compute_rankings
  → compute_market_momentum_frame
  → build_candidate_pool                    # A/B/C/D raw union
  → legacy branch（照跑，供 fallback/監控）
  → compute_market_regime + market_breadth
  → build_phase2_pool                       # soft hints + deterministic signals + 第一輪 hard gate
  → run_phase2_pipeline
       → sector context
       → entry state
       → tracking/new-discovery 分流
       → sector cluster
       → base momentum eligibility
       → role annotation
       → Phase 2 regime gate
       → momentum freshness / watch quality
  → role_to_prelim_type                     # 舊 UI/LLM 三分類相容映射
  → 取 llm_eligible
  → _order_llm_input                       # 只排序、不截斷
  → Candidate Research v7                   # 外部事實研究
  → Candidate Assessment v7                 # 逐檔 eligibility / legal veto
  → backend partition_assessments           # 驗證 true REMOVE 前提
  → build_compact_selection_cards
  → Global Recommendation Selector v7       # 全體一次比較
  → RECOMMEND / NOT_SELECTED
  → Recommendation Reason v7                # 只替 RECOMMEND 寫長理由
  → persist SignalSnapshot / WatchHit
  → Tracking Review v7 + p4_state_v1        # 每日 observation lifecycle
  → post-decision P6 outcome refresh        # 不回饋前述任何決策
```

最終資料桶不是單一「有選／沒選」，而是：

| Bucket | 意義 | 是否進今日主清單 | 是否建立新 observation |
|---|---|---:|---:|
| `RECOMMEND` | 全體比較後具有今日相對優勢的正式推薦 | 是 | 是 |
| `NOT_SELECTED` | 候選仍有效，但今日相對優勢不足 | 否 | 否 |
| `REMOVE` | Backend 驗證成立的 true veto | 否 | 否 |
| Technical Failure | Research、Assessment、Reason、Tracking 或 Global 技術失敗 | 否 | 否 |

`NOT_SELECTED`、`REMOVE` 與 P4 的 `STOP_OBSERVING` 是三種不同概念；前兩者是今日
selection 結果，後者是既有推薦 episode 的追蹤生命週期結果。

### 1.1 Fail-safe

`SIGNALS_PIPELINE_MODE=phase2` 時，legacy branch 仍會先算完。若 Phase 2 任一處丟
exception，pipeline 會 rollback Phase 2 寫入，並使用本次已算好的 legacy
`after_regime` 繼續送 LLM，而不是讓整個 daily job 失敗。

這表示「目前正常 production」與「Phase 2 例外當次 fallback」是兩套不同規則。
本文先完整描述 Phase 2，legacy 放在附錄。

### 1.2 從 DB 抓股票到 UI 的逐步流程

下表是操作層級的完整導覽；門檻公式與例外情況在後續對應章節展開。

`.github/workflows/daily_signals.yml` 每天台北 19:23 觸發一次，讓週末補班開盤也能
執行；一般週末與國定假日因 target date 沒有交易資料而走 no-data，不呼叫選股 LLM。
Scheduled workflow 必須存在於 GitHub default branch 才會自動觸發。Production 明確設
`SIGNALS_PIPELINE_MODE=phase2`，scheduled run 預設 `SIGNALS_PROMPT_FAMILY=v7`。

| Step | 執行者 | 輸入 | 做什麼 | 輸出／下一站 |
|---:|---|---|---|---|
| 0 | Prompt family router | deployment env | 解析 `SIGNALS_PROMPT_FAMILY`；未知 family 直接 fail closed | v7 stage versions、SHA 與 metadata |
| 1 | `ingest_data` | target date、DB | 找最近 60 個交易日與所有 active `stocks_master` | 2/3/5/10/60 日窗口、active universe |
| 2 | Momentum frame | active universe、最多 66 個交易日 | 批次算價格、量能、RS、波動、法人／成交比、市值與可用月營收 | 全市場 percentile/rank frame |
| 3 | A ranking | 產業與個股法人流 | 近 2 日產業前 10、個股前 30；產業再套當日賣超煞車 | A 通道 IDs |
| 4 | B/C/D admission | momentum frame | 價格動能最多 40、加速最多 20、基本面最多 20 | B/C/D 通道 IDs |
| 5 | Raw union | A/B/C/D | 聯集、A 前 6 集團擴散；只排非 active master 與人工黑名單 | 完整 raw candidates |
| 6 | Candidate enrich | raw candidates | 批次補 OHLCV、法人、融資、產業流、asset type、tracking episode、Momentum Score | 每檔 deterministic evidence |
| 7 | Raw ordering | enrich 後候選 | score、法人 3 日、stock ID 排序；**不截斷** | Phase 2 processing order |
| 8 | Phase 2 hard gate | soft hints、deterministic signals | 套六類 true hard exclusion | hard-excluded 與 survivors 分離 |
| 9 | Phase 2 context | survivors | 算 sector context、entry state、tracked continuation、cluster | context-enriched candidates |
| 10 | Base/regime | context candidates、TAIEX | base momentum eligibility；RISK_OFF 才有額外 leader/tracked + RS90 gate | regime survivors |
| 11 | Freshness/quality | regime survivors | 算 Freshness、七類 Watch Quality；預設 shadow 不刪 RESERVE | `llm_eligible` |
| 12 | LLM ordering | `llm_eligible` | conviction、score、market RS、warning 數、stock ID 排序；不截斷 | Research batches |
| 13 | Research v7 | 預設每批 4，契約失敗時二分重試 | 查業務／ETF 曝險、題材、催化、矛盾與來源 | research success 或 `RESEARCH_FAILED` |
| 14 | Assessment v7 | 每批 4 | 逐檔評估 eligibility / veto，不做跨股比較 | assessment success 或 `DECISION_FAILED` |
| 15 | Backend veto guard | assessment results | 驗證 backend max、factual veto、quality veto 前提 | true `REMOVE` 與 global eligible |
| 16 | Global v7 | **所有** compact cards | 一次全體比較；無 Top-K、ratio、asset/source/cluster quota | `RECOMMEND` / `NOT_SELECTED` |
| 17 | Reason v7 | 只有 RECOMMEND | 產生題材、資金、籌碼、融資、技術、動能說明 | 正式推薦長理由 |
| 18 | Persist + P4 | final buckets、active observations | 寫 snapshot/watch hit；新推薦建 episode；所有 active episode 每日 review | P3 snapshot + P4 lifecycle |
| 19 | P6 post-decision | snapshot、價格、P4 rows | 更新 Day10 outcome、observation analytics、人工 review queue | `/signals/*` 產品 UI |

資料來源是本地資料庫既有 ETL 結果；selection pipeline 本身不在這個步驟重新下載全市場
行情。主要讀取：

- `stocks_master`：有效證券、名稱、產業與子產業。
- `daily_price`：OHLC、成交量、成交額與交易日曆。
- `inst_stock_flow` / `industry_daily_flow`：外資、投信、自營商個股與產業資金流。
- `margin_trade`：融資、融券與券資比相關欄位。
- `monthly_revenue`：月營收 YoY/MoM；一律經「次月 10 日可用」gate。
- `stock_shares_outstanding`：市值與法人買超／市值欄位，目前不進 Momentum Score。
- `security_classification` / `etf_classification`：canonical asset type 與研究適用性。
- `signal_watch_hits`、`signal_observations`、`signal_observation_reviews`：episode 與追蹤前態。

## 2. Step A：資料與 ranking

來源：`backend/app/signals/candidate_pool.py`

### 2.1 Universe 與資料窗口

`ingest_data()`：

- 取 `stocks_master.is_active = true` 的股票。
- 取最近 60 個交易日，切成 2/3/5/10/60 日窗口。
- momentum frame 另用 66 個交易日，才能計算 60 日報酬與 5 日 RS rank change。
- 人工黑名單股票不進 momentum universe。
- **ETF 與金融股目前不從 universe 排除。**

### 2.2 產業 ranking（A 通道的一部分）

實際排序窗口是 `RANKING_WINDOW_DAYS = 2`；部分欄位仍沿用歷史名稱 `_3d`，
不能只看欄位名稱推斷期間。

1. 各產業依近 2 日三大法人合計淨買超由高到低排序。
2. 直接取前 10 個產業；金融產業與其他產業同一套排名規則。
3. 另算當日產業淨額，真正淨賣超的產業由最弱往上取最多 10 個。
4. 入選產業若落在當日賣超名單就刪除，不回補。

金融產業若落入當日賣超煞車仍會被剔除，與其他產業相同；不因金融屬性額外跳過。

### 2.3 個股 ranking（A 通道的一部分）

`compute_hot_money(days=2, limit=30)`：近 2 日三大法人淨買超前 30 名。

## 3. Step B：A/B/C/D 候選聯集

來源：

- `backend/app/signals/candidate_pool.py::build_candidate_pool`
- `backend/app/signals/momentum.py::select_momentum_candidates`

### 3.1 A — 法人資金

聯集以下股票：

- 近 2 日法人個股榜前 30 名。
- 入選產業（包含金融）的所有 `stocks_master` 成分股。
- 個股榜前 6 名所屬集團的所有已設定成員。

### 3.2 B — 價格動能

下列任一成立即可先命中，再按：

```text
rs_market_percentile_20d DESC
→ return_20d DESC
→ stock_id
```

取前 40：

1. `rs_market_percentile_20d >= 85`；或
2. `rs_industry_percentile_20d >= 80`；或
3. `distance_to_20d_high >= 0` 且
   `volume_1d_to_20d_avg >= 1.2`；或
4. `return_percentile_60d >= 85` 且 `return_5d > 0`。

### 3.3 C — 動能加速

兩者同時成立：

- `rs_rank_improvement_5d >= 200`
- `rs_market_percentile_20d >= 70`

依 `rs_rank_improvement_5d DESC → stock_id` 取前 20。

### 3.4 D — 基本面動能

月營收資料先套 `available_date = 次月 10 日`，避免資料穿越。以下任一成立：

1. `revenue_yoy > 15` 且 `revenue_yoy_accel_2m = true`；或
2. `revenue_yoy_turned_positive = true`；或
3. `revenue_yoy_industry_percentile >= 80`。

依 `revenue_yoy DESC → stock_id` 取前 20。

### 3.5 候選池入口排除

raw union 後只做：

- 不在 active `stocks_master`：不加入。
- 人工黑名單：不加入。

**目前不因 ETF 或金融資產類型排除。** 每檔另標：

```text
asset_type = COMMON_STOCK | FINANCIAL | ETF
```

分類優先讀 `etf_classification` / `security_classification.is_financial`；資料表缺席才
退回名稱、產業、代號 heuristic，並寫 warning。這個欄位只供 evidence applicability、
研究模式與 UI 使用，不是 Phase 2 REMOVE 理由。

### 3.6 四通道獨立性

`build_candidate_pool()` 只在 active masters 為空時提前結束。A rankings 全空時仍會先
計算 B/C/D，再建立聯集；B-only、C-only、D-only 與 B+C+D 都可獨立啟動。

## 4. Momentum score、grade 與 phase

來源：`backend/app/signals/momentum.py`

### 4.1 Momentum score（0～100）

```text
價格 30
  = 30 × (
      0.5 × market RS percentile
    + 0.3 × 60d return percentile
    + 0.2 × 5d return percentile
  )

相對強度 25
  = 25 × (
      0.6 × market RS percentile
    + 0.4 × industry RS percentile
  )

法人 20
  = 20 × (
      0.6 × 2d 法人買超/成交比 percentile
    + 0.4 × min(近3日買超日數, 3) / 3
  )

量價 15
  = 15 × 5d/60d volume ratio percentile

基本面 10
  = 10 × (
      0.6 × revenue YoY percentile
    + 0.2 × YoY acceleration > 0
    + 0.2 × revenue MoM > 0
  )
```

百分位在公式中先除以 100。核心欄位缺值時貢獻 0，不給中性分。

基本面證據先標適用性：

- `AVAILABLE`：有實際月營收證據，正常納入 10 分。一般股、金融股規則相同。
- `MISSING`：一般股/金融股沒有資料，基本面貢獻 0，**不**重配權重。
- `NOT_APPLICABLE`：只有 ETF 的公司基本面。10 分從分母排除，核心 90 分按
  `100/90` 正規化到 100，再套 risk penalties。

Production 版本為 `v3_applicability_aware`。`SIGNALS_MOMENTUM_SCORE_MODE=legacy`
可供 replay 重現舊公式；此時 `SIGNALS_MOMENTUM_SCORE_AVAILABLE_WEIGHT` 才有作用。
歷史 snapshot 不回填。

### 4.2 Risk penalties

可同時累加：

| 條件 | 扣分 |
|---|---:|
| 爆量長上影：`volume_1d_to_60d_ratio > 2`、上影線 > 實體 2 倍、`close < high×0.97` | -10 |
| `rs_rank_improvement_5d <= -200` | -10 |
| `price_change_3d > 12%` | -5 |

最後 clamp 到 0～100，四捨五入一位。

### 4.3 Grade

| 分數 | Grade |
|---|---|
| `>=75` | A |
| `>=60` | B |
| `>=45` | C |
| `<45` | D |

### 4.4 Momentum phase（優先序固定）

1. `weakening`
   - `rs_rank_improvement_5d <= -100`；或
   - rank change < 0 且 `return_5d < 0`。
2. `extended`
   - `return_5d >= 12%`；或
   - `price_change_3d > 12%`。
3. `accelerating`
   - rank improvement >= 100 且 market RS >= 60。
4. `trending`
   - market RS >= 70。
5. 其餘為 `emerging`。

market RS 缺值時 phase 為 `None`。

## 5. Raw pool 完整召回與排序

每檔完成 metrics、tracking status、momentum score 後：

- 無論候選數量，A/B/C/D 聯集全部保留。
- 依下列 key 排序，僅決定處理、debug、snapshot 順序：

```text
momentum_score DESC
→ total_institution_flow_3d DESC
→ stock_id ASC
```

不得將此 ordering 解讀為 eligibility 或固定 Top-K。Snapshot 的
`raw_union_truncated_count` 與 `capacity_truncated_count` 正常皆為 0。

## 6. Tracking status 與 episode

來源：`candidate_pool._load_tracking_status`

active `signal_watch_hits` 會產生：

- `is_tracked`
- `first_seen_date`
- `days_since_first_seen`
- `hit_count`
- `consecutive_hit_count`
- `independent_hit_count`
- `max_positive_return_pct`
- `max_negative_return_pct`

兩次命中之間未命中交易日 `>=5` 才算新 episode；4 日仍算同 episode。

`failed_follow_through = true` 的條件：

```text
days_since_first_seen >= 3
AND max_positive_return_pct < +3%
AND max_negative_return_pct < -6%
```

它是當前 active cycle 的 hard failure。cycle 被 archive 後舊 hits 移除，之後重新
命中是新 cycle，不是永久封鎖股票。

## 7. Phase 2 pool：soft hints、deterministic signals、第一輪 hard gate

來源：`backend/app/signals/phase2/pipeline_v2.py::build_phase2_pool`

順序很重要：

```text
raw candidate
→ _detect_soft_hints
→ attach_deterministic_signals
→ build_hard_exclusion_result
```

### 7.1 Soft hints（只標記）

來源：`backend/app/signals/filters.py::_detect_soft_hints`

| Hint | 實際條件 |
|---|---|
| `weakening` | flow3d > 0 且 flow1d < `-0.5 × flow3d` |
| `retail_overheated` | margin 3d change > 5% 且 flow3d <= 0 或缺值 |
| `distribution` | 當日量/60日均量 >2 且 price1d <=0；或長上影條件 |
| `range_bound` | `(high_10d-low_10d)/low_10d < 5%` |

長上影條件：

```text
high-close > (close-open)×2
AND close < high×0.97
```

注意：紅 K 時 `(close-open)` 為負，第一個 inequality 很容易成立；這是目前程式的
實際數學行為。

### 7.2 Deterministic signals

來源：`backend/app/signals/deterministic_signals.py`

這些欄位會送 LLM，LLM 不得覆寫：

- `chip_trend`
- `technical_status`
- `entry_quality`
- `sector_rotation_status`
- `institution_flow_momentum`
- `risk_gate_action`
- `max_decision`
- `risk_flags`

最重要的 hard-risk 路徑：

```text
distribution + institution_flow_reversal
  → risk_gate_action = EXCLUDE

failed_rotation + momentum_phase == weakening
  → risk_gate_action = EXCLUDE
```

其他行為：

- `retail_overheated` 或 `extended_chase` → `MAX_B`
- 其餘任一 risk flag → `DOWNGRADE_ONE_LEVEL`
- 無 risk flag → `PASS`
- `max_decision = REMOVE` 僅在 `risk_gate_action=EXCLUDE`，否則 `WATCH`

## 8. Phase 2 六類 True Hard Exclusion

來源：`backend/app/signals/phase2/regime_gate.py`

實際優先序如下；找到第一項就停止：

1. `MANUAL_BLACKLIST`
2. `FAILED_FOLLOW_THROUGH_CURRENT_EPISODE`
3. `STRUCTURE_DAMAGED`
4. `LIQUIDITY_FAILURE`
5. `COMPOSITE_RISK_EXCLUDE`
6. `REVERSAL_FAILURE`

### 8.1 MANUAL_BLACKLIST

`exclusions.is_blacklisted(stock_id)`。通常已在 raw pool 入口先擋，這裡是防禦性二次檢查。

### 8.2 FAILED_FOLLOW_THROUGH_CURRENT_EPISODE

即第 6 節的 `failed_follow_through`。

### 8.3 STRUCTURE_DAMAGED

Entry state 同時滿足：

```text
abs(distance_to_20d_high) / atr_pct_14d >= 4
AND rs_rank_improvement_5d < 0
```

### 8.4 LIQUIDITY_FAILURE

```text
avg_turnover_5d < 50,000,000 TWD
```

缺值視為 `UNKNOWN` 並放行，不因資料缺漏清池。

### 8.5 COMPOSITE_RISK_EXCLUDE

`deterministic_signals.risk_gate_action == EXCLUDE`，即：

- distribution + 法人反轉；或
- 產業輪動失敗 + momentum weakening。

### 8.6 REVERSAL_FAILURE

三組條件都要成立：

A. 實質法人反轉

```text
flow1d < 0
prior = flow3d - flow1d > 0
abs(flow1d) / prior >= 0.5
```

B. 相對大盤轉弱

```text
price_change_1d - TAIEX_return_1d <= -1.5pp
```

C. 額外 confirmation 至少一項：

- `entry_state == STRUCTURE_DAMAGED`；或
- 下跌且 `volume_1d_to_5d_ratio > 1.5`；或
- `(high-close)/(high-low) >= 0.8`；或
- `industry_flow_1d > 0` 且 `price_change_1d < -1%`。

缺任一必要資料不觸發。

### 8.7 Hard gate 的兩次接線

目前 pipeline 有兩次防線：

1. `build_phase2_pool()`：已有 soft hints、deterministic signals、TAIEX 1d return，
   但 **尚未計算 entry_state**。
2. `apply_regime_gate_v2()`：entry_state 已存在，可抓 `STRUCTURE_DAMAGED`，但這次
   呼叫沒有再傳 TAIEX return。

因此：

- `STRUCTURE_DAMAGED` 實際在第二次防線被剔除。
- `REVERSAL_FAILURE` 實際主要在第一次防線判斷；該時點 C 條件中的
  `entry_state == STRUCTURE_DAMAGED` 尚不可用，但其他 volume/close/sector
  confirmations 可用。
- structure damage 本身仍會在第二次防線獨立 hard exclude。

這是目前接線真相，不能只讀 `build_hard_exclusion_result()` 的理想輸入欄位推斷。

### 8.8 只 warning、不直接排除的舊門檻

| Warning | 條件 |
|---|---|
| `EXTENDED_3D` | price3d > 15% |
| `EXTENDED_PROFIT_TAKING_WARNING` | price10d >25% 且 flow1d <0 |
| `INSTITUTION_REVERSAL_WARNING` | flow3d >0、flow1d <0、price1d <-1.5% |
| `LOW_RAW_VOLUME` | 當日張數低於/等於股價級距門檻 |

當日張數 warning：

- 股價 `<1000`：`<=1500` 張。
- `1000<=股價<5000`：`<=800` 張。
- 股價 `>=5000`：`<=500` 張。
- 價格或 volume 缺值：不觸發。

ETF／金融資產類型連 warning 都不是。

## 9. Sector context

來源：`backend/app/signals/phase2/sector_context.py`

Phase 1 classification confidence 只有 `HIGH/MEDIUM` 可用；`LOW` 直接 fallback。

peer scope：

1. usable mapping 且 sub-sector 樣本 `>=5`：
   `SUB_SECTOR`、quality=`HIGH`。
2. 否則 primary-sector 樣本 `>=5`：
   `PRIMARY_SECTOR`、quality=`MEDIUM`。
3. 否則：
   `MARKET_ONLY`、quality=`UNUSABLE`，peer/sector percentile 為 null。

`sector_context_quality` 不是 classification confidence 的別名；它描述最後實際採用
哪一層 peer scope。

兩個獨立指標：

- `peer_rs_percentile_20d`：股票在 peer group 的 market RS percentile。
- `sector_strength_percentile_20d`：該 group 平均 market RS 相對其他有效 group
  的 percentile。

計算 sector-strength percentile 時，同層有效 group population 也必須至少 5 組；
不足時 strength percentile 為 null。

Production `run_phase2_pipeline()` 目前用 **Phase 2 候選池本身**當 frame，不是完整
全市場 frame；所以這些 percentile 是「候選池內/候選 sector groups」脈絡。

## 10. Entry state

來源：`backend/app/signals/phase2/entry_state.py`

先算：

```text
pullback_atr_multiple
  = abs(distance_to_20d_high) / atr_pct_14d
```

distance 或 ATR 缺值、ATR<=0 → state=null。

判斷優先序：

1. `STRUCTURE_DAMAGED`：
   multiple >=4 且 RS rank change <0。
2. `REACCELERATING`：
   RS rank change >=30 且 multiple >0.5。
3. `NEAR_HIGH`：multiple <=0.5。
4. `NORMAL_PULLBACK`：multiple <=2。
5. 其餘：`DEEP_PULLBACK`。

### 11.2 已追蹤候選

## 14. New-discovery role annotation

## 15. Market regime

來源：`backend/app/signals/market_regime.py`

TAIEX 取最多 65 筆完整 OHLC，分類優先序：

```text
RISK_OFF
→ high-volatility VOLATILE_RANGE
→ BULL_TREND
→ VOLATILE_RANGE
```

### 15.1 RISK_OFF

```text
close < MA20
AND (
  MA10 < MA20
  OR return_5d <= -3%
)
```

### 15.2 高波動 VOLATILE_RANGE

任一成立：

- 近 5 日平均 `(high-low)/close >=2.8%`
- 近 5 日至少 1 天：
  `close_vs_high <=-2%` 且 `return_1d <=-1%`
- 近 3 日最差單日報酬 `<=-2.5%`

### 15.3 BULL_TREND

全部成立：

- close >= MA10 >= MA20
- MA20 五日 slope >0
- return10d >0
- 未命中高波動 overlay

資料少於 20 筆或必要值缺失 → `VOLATILE_RANGE`。

### 15.4 Market breadth 的實際作用

`market_breadth.py` 會算 breadth score，BULL 下 `<50` 標 `NARROW_BULL`，否則
`BROAD_BULL`。

但 **目前 Phase 2 `apply_regime_gate_v2()` 只收到三態 `market_regime`，不收到
`regime_detail`**。所以 breadth/NARROW_BULL：

- 會寫進 market context、snapshot 與 legacy gate；
- **不會改變目前 Phase 2 的 candidate survival。**

## 16. Phase 2 regime gate 與 conviction

來源：`backend/app/signals/phase2/regime_gate.py::apply_regime_gate_v2`

### 16.1 BULL_TREND / VOLATILE_RANGE

Phase 2 不加額外角色/分數 hard gate。通過：

- true hard exclusion；

### 16.2 RISK_OFF

|---|---|---|---|

## 17. Phase 2.5 Momentum Freshness

來源：`backend/app/signals/phase2/momentum_freshness.py`

只有 `WATCH_QUALITY_MODE != off` 才計算；預設 `shadow` 會算。

### 17.1 Evidence thresholds

- strong excess return：個股 1d − TAIEX 1d >= +1pp
- weak excess return：<= -1pp
- RS deteriorating：rank change <=-50
- close strong：CLV >=0.6
- close weak：CLV <=0.3
- volume strength：上漲日量比 >=1.1
- volume weakness：下跌日 signed volume ratio <=-1.3
- institution confirming：flow momentum accelerating/stable
- institution reversal：flow momentum reversal
- sector confirming：sector rotation inflow
- sector failed：failed_rotation
- entry reaccelerating / pullback / near-high

### 17.2 State 優先序

1. `DETERIORATING`
   - 至少 2 個負面 votes；
   - 且沒有 strong excess return。
2. `FRESH_STRONG`
   - strong excess return；
   - 至少 1 個 positive confirmation；
   - 至少 1 個 close/volume strength；
   - 0 negative votes。
3. `HEALTHY_PULLBACK`
   - entry normal/deep pullback；
   - 非 weak excess return；
   - 0 negative votes。
4. `STALE`
   - score >=55；
   - 0 positive confirmation；
   - 0 strength votes；
   - negative votes <=1。
5. 其餘 `FRESH_STABLE`。

## 18. Phase 2.5 Watch Quality

來源：`backend/app/signals/phase2/watch_quality.py`

### 18.1 七個 evidence families

| Family | 條件 |
|---|---|
| `MOMENTUM_STRENGTH` | score>=70 或 market RS>=85 |
| `FRESHNESS` | fresh strong/stable/healthy pullback |
| `RELATIVE_STRENGTH` | sector usable 時 peer RS>=70；否則 market RS>=90 |
| `PARTICIPATION` | 5d/60d volume>=1.3 或 freshness 的 volume strength |
| `SECTOR_CONFIRMATION` | sector inflow 或 cluster active |
| `INSTITUTION_CONFIRMATION` | institution accelerating/stable 或 buy days>=2 |
| `PRICE_STRUCTURE` | entry near/normal/reaccelerating 且 close 不弱 |

`watch_quality_score = evidence_count / 7 ×100`，只供 debug/顯示；state machine 才
決定 READY/SETUP/RESERVE。

共同門檻：

- READY evidence >=4
- SETUP evidence >=2
- Emerging high-quality >=3
- Unclassified strong >=5

嚴重 warning pairs 在 tracked active/reaccelerating、unclassified、sector follower
與一般 formal-leader/rotation-laggard 分支會限制不可 READY：

- institution reversal + extended profit taking
- institution reversal + low raw volume

目前 `EMERGING_MOMENTUM` 分支沒有套 `severe_combo` READY 限制；它只看 evidence
count 與 freshness。這是實際 code 分支差異，不應把 severe pair 誤寫成全角色共用。

### 18.2 State machine 摘要

- Tracked `DETERIORATING` → RESERVE。
- Tracked `HEALTHY_PULLBACK`：evidence>=2 → SETUP，否則 RESERVE。
- Tracked active/reaccelerating：
  - ready freshness + evidence>=4 + 無 severe pair → READY；
  - evidence>=2 → SETUP；
  - 否則 RESERVE。
- `EMERGING_MOMENTUM`：
  - evidence>=3 且 freshness 至少為 setup-compatible；
  - evidence>=4 → READY，否則 SETUP；
  - 否則 RESERVE。
- `UNCLASSIFIED_MOMENTUM`：
  - evidence>=5 且 ready freshness → READY（severe pair 時 SETUP）；
  - evidence>=3 → SETUP；
  - 否則 RESERVE。
- `SECTOR_FOLLOWER`：
  - ready freshness + evidence>=4 + 無 severe pair → READY；
  - setup freshness + evidence>=2 → SETUP；
  - 否則 RESERVE。
- Formal leaders / rotation laggard：
  - ready freshness + evidence>=4 + 無 severe pair → READY；
  - setup freshness + evidence>=2 → SETUP；
  - 否則 RESERVE。

`EXTENDED_3D` 本身不會降級 READY/SETUP，只附註 entry risk。

### 18.3 現在它是否真的擋股票？

| `WATCH_QUALITY_MODE` | 行為 |
|---|---|
| `off` | 不計 freshness / quality；全部 regime survivors 送 LLM |
| `shadow`（預設） | 計算並記錄，但 READY/SETUP/RESERVE **全部送 LLM** |
| `production` | 只有 READY/SETUP 送 LLM；RESERVE 留在 survivors/debug |
| 非法值 | fallback 成 `shadow` |

所以在沒有 deployment env 覆寫的前提下，不能把 RESERVE 寫成目前 production
自動刪除規則。

## 21. Research、assessment 與全體推薦

邊界：`llm_caller.run_research_batch(after_regime, market_context)`

- Prompt v7 Research batch size：預設 4；Structured Outputs 失敗時二分重試至單檔，
  單檔再依精確錯誤修正一次。
- Legacy replay Research batch size：8。
- Assessment batch size：4。
- 所有 batches 都執行；單批失敗不取消前後已完成／待執行批次。
- Console／GitHub Action log 逐批輸出 `batch x/y completed`、候選數與 unavailable 數；
  snapshot 另保存 batch index、股票清單、開始／完成時間與錯誤摘要。
- 單檔修正後仍含 cutoff 之後的 evidence 時，Backend 不採用任何模型敘事或來源，
  改寫為無來源、LOW confidence、`UNCONFIRMED` 的保守研究結果。
- Research 或 Assessment 技術失敗分別記為 `RESEARCH_FAILED` /
  `DECISION_FAILED`，不會轉成 `REMOVE`。
- 有失敗時 snapshot 保留可用結果，job status 為 `partial_failure`；daily runner
  會回 exit code 4，GitHub Action 必須標紅，不得把不完整結果視為成功。
- Prompt 預設：`SIGNALS_PROMPT_FAMILY=v7`，由 shared policy 與獨立 stage prompts 組裝。
- 回滾只使用 `SIGNALS_PROMPT_FAMILY=legacy_split`；未知 family 直接拒絕執行。

Pipeline 內部／`legacy_split` 的完整 evidence view 會累積：

- stock/name/industry/sub-industry/asset type
- display type
- `backend_max_decision`
- 法人、價格、量能、融資融券等核心 evidence
- tracking status
- soft hints
- deterministic signals
- momentum signals
- regime conviction
- Phase 2 role/tracking/entry state
- freshness/watch-quality state 與七個 quality evidence

Pipeline 的完整 market context 會累積 backend authoritative：

- `market_regime`
- `market_regime_label/reason`
- `breadth_score`
- `market_regime_detail`
- DB market snapshot 與 margin climate

**Active v7 不會把上述完整物件原封不動送進每個 stage。** Research、Assessment、
Global、Reason、Tracking 各自再經 allowlist 投影，只取得該階段必要欄位；實際欄位見
21.1 表。

v7 的選股權限邊界：

- Backend Phase 2 決定 candidate eligibility、hard gate、role、regime、conviction、
  `backend_max_decision`。
- LLM 只驗證公司/ETF 業務、題材、供應鏈、集團關係與重大外部矛盾，並解釋。
- LLM assessment 不可把 backend `REMOVE` 升成 eligible。

### 21.1 Prompt v7 家族的五次 LLM 呼叫

`shared-policy-v7.md` 不是一次獨立 API call，而是每個 v7 stage system prompt 的共同
前半段。Production 每日最多有五種 LLM 呼叫；沒有 active observation 時 Tracking
可能沒有 item，正式推薦為 0 時 Reason 也沒有 item。

| 呼叫順序 | Active stage/version | 分批方式 | LLM 看到什麼 | LLM 能輸出什麼 | Backend 最後把關 |
|---:|---|---|---|---|---|
| 1 | Research / `v7_research` | 預設每批 4、concurrency 2；契約失敗二分至單檔並精確修正一次 | 日期、股票身分、asset type、產業、Phase 2 role、題材候選、來源 A/B/C/D、market regime | 業務／ETF 曝險、題材、供應鏈、催化、矛盾、來源、研究信心 | Structured Outputs、一對一 alignment、enum、URL、published date；修正後仍含未來來源則整檔中性化為 UNCONFIRMED |
| 2 | Assessment / `v7_assessment` | 每批 4，concurrency 2 | backend max、freshness、quality evidence、Research validations | `ELIGIBLE_FOR_GLOBAL_SELECTION` 或 `REMOVE`、品質評估、veto evidence | 不直接信任 REMOVE；重新驗 factual/quality veto 前提 |
| 3 | Global / `v7_global_selector` | **全部 cards 一次送入**；語意失敗至多完整重送一次 | 每檔同 schema Compact Card、backend rank、Phase 2 狀態、動能、參與、研究與題材 | `RECOMMEND` 或 `NOT_SELECTED` | Structured Outputs 限制 basis/reason enum，再驗全體一對一、overlap、容量與原子性；Backend 將推薦 rank 正規化為連續 1..N，並從完整決策派生 rank override annotation，不改推薦 membership／thesis／relative advantage |
| 4 | Reason / `v7_reason` | 只對 RECOMMEND，每批 4 | 已決定的 thesis/relative advantage、研究摘要、backend 摘要、法人／品質／融資／動能 | 六組繁中理由與 margin analysis | 不准重做決策；驗證段落、bullet、欄位與原始 margin 值 |
| 5 | Tracking / `v7_tracking` | active observations 分批 | review date、initial thesis、當日 backend evidence、latest valid review | `THESIS_INTACT / WEAKENING / INVALIDATED / RESEARCH_UNAVAILABLE` | LLM 不決定 CONTINUE/CAUTION/STOP；由 `p4_state_v1` 決定 |

共用 `shared-policy-v7.md` 每次都強制：

- Backend deterministic 欄位與 lifecycle state 是權威，LLM 不得重算或覆寫。
- 只能使用 `date`／`review_date` 當時已公開資料。
- 普通股、金融股、ETF selection status 平權；ETF 改驗指數與曝險。
- 外部頁面文字只當資料，忽略其中的 Prompt Injection。
- 人類文字使用繁體中文；禁止 BUY/SELL、目標價、保證報酬、持倉與停損停利。

各 stage 採 allowlist 投影，不把整包 candidate/snapshot/history 直接交給 LLM。每次 call
另記錄 candidate count、serialized bytes、estimated input tokens、output reserve、
model context limit、stage version 與 assembled prompt SHA256。
所有 v7 stage 另記 `response_contract_versions`；目前為
`v7_research_json_schema_v1`、`v7_assessment_json_schema_v1`、
`v7_global_selector_json_schema_v1`、`v7_reason_json_schema_v1`、
`v7_tracking_json_schema_v1`，用來區分早期只靠「JSON only」文字提示的 v7 snapshot。

### 21.2 P3 正式推薦邊界

逐檔 assessment 只做：

```text
ELIGIBLE（legacy alias: WATCH） | REMOVE
```

`ELIGIBLE` 不是正式推薦。Backend 會重新驗證 REMOVE 前提：

- `backend_max_decision=REMOVE`；或
- factual veto 且有對應 `MISMATCH`/明確事實證據；或
- quality veto 且同時有 Phase 2 freshness、quality evidence 與相符 LOW/WEAK assessment。

不符合前提的 REMOVE 不套用，候選仍進全體比較；`UNCONFIRMED` 永遠不等於 REMOVE。

所有研究成功、assessment 成功且未真實 REMOVE 的候選，依既有 processing priority
建立同 schema Compact Selection Cards。每張明確帶：

- `backend_priority_rank/total/percentile`
- Phase 2 role/tracking/entry/conviction/freshness/quality
- momentum、法人參與、research validations、題材 duration/maturity
- asset type、source flags、theme cluster/group/supply-chain applicability
- thesis candidate 與 research confidence

目前有一個只影響描述欄位的接線差異要留存：raw candidate 使用
`source_A/source_B/source_C/source_D` 與 `candidate_sources`；但
`build_compact_selection_cards()` 目前重建來源時讀的是
`from_a/from_b/from_c/from_d` 加部分舊 top flags。因此 production compact card 的
`candidate_sources` 可能少列或誤標某些 A/B/C/D 來源。這不影響 admission、backend
rank、REMOVE 或 Global decision，因為 source 依法不得當 gate/rank/quota；新版 UI
目前也沒有把 card source 當主要欄位。若未來要在 UI 正式展示來源，應先統一這組 key。

Global selector `v7_global_selector` 一次看到全部 cards，只能輸出：

- `RECOMMEND`：進主 watchlist、取得連續正整數 `recommendation_rank`、產生長理由並新增
  `signal_watch_hits` observation。
- `NOT_SELECTED`：候選仍有效但今日相對優勢不足；保留 reason code/reason，不帶
  `veto_reason`，不新增 observation，也不停止既有追蹤。

同 cluster 沒有檔數上限；只有實質 thesis 重疊時可用 `THESIS_OVERLAP`，且必須指出
`overlap_with/overlap_reason`。Backend rank 是比較骨架，不是 cutoff；較低 rank 跨過
較高未入選者時，Backend 由完整 decision set 派生 `rank_override=true`；若模型未另填
override 理由，只重用該推薦既有的 `relative_advantage`，不創造新的 selection
理由。派生股票清單記錄於 `llm_diagnostic.backend_derived_rank_overrides`。

模型輸出的推薦集合仍是唯一 membership authority；Backend 只把該集合的重複、缺漏或
非正整數 rank 依「有效模型 rank → backend priority rank → 原輸出順序」穩定重編為
`1..N`。變更紀錄寫入
`llm_diagnostic.backend_normalized_recommendation_ranks`，不新增或刪除推薦。

推薦數允許 `0..全部`，沒有固定 Top-K、比例、分數 cutoff、資產/source/cluster quota，
也沒有另外發明加權總分。

### 21.3 原子失敗與容量護欄

Backend 以 candidate count、compact JSON bytes、保守 token estimate、output reserve 與
設定的 model context limit 做一次性容量檢查。超限直接
`GLOBAL_SELECTION_CONTEXT_EXCEEDED`，不改用 tournament。

Selector 回應若漏檔、重複、未知股票、decision/reason 不合法、推薦 rank 不連續或缺少
rank override，整次為 `GLOBAL_SELECTION_FAILED`：

- job=`partial_failure`、`selection_complete=false`
- 正式 watchlist 為空，不以全收/全拒/全 REMOVE fallback
- 保存 research 後的 compact cards、diagnostic 與 error
- 不產生長理由、不寫 observation，可安全重跑

API 保留既有 `watchlist/removed/summary`，新增 `not_selected`、
`technical_failures` 與 `selection_summary`。舊 snapshot 沒有新欄位時回空陣列。

## 22. P4 每日 Observation Lifecycle

P3 回答「今天是否值得正式推薦」，P4 回答「已推薦 episode 是否仍值得持續觀察」。
兩者為獨立決策：

```text
P3 RECOMMEND → 建立或延續 observation（同日不 review）
下一交易日起，不論是否再命中 A/B/C/D → 每日 review
→ CONTINUE | CAUTION | STOP_OBSERVING | REVIEW_FAILED
```

- `STOP_OBSERVING` 只代表停止列入魚尾追蹤，不是 SELL、停損或看空。
- `REVIEW_FAILED` 是技術失敗，保持上一個有效狀態且不增加 caution count。
- 單日下跌／法人賣超、市場 RISK_OFF、persistence warning、Day1/Day3 表現都不能單獨 STOP。
- 即時 STOP 只接受六個 backend hard reason、`TRACKING_INVALIDATED`，或具截至 review date
  可追溯證據的外部 thesis invalidation。
- 一般持續性 STOP 必須是最新兩次成功 review 都為 CAUTION，至少兩個核心維度持續失效，
  且其中至少有動能結構或參與維度，並且沒有 recovery。
- 核心維度只有 `MOMENTUM_STRUCTURE`、`PARTICIPATION`、`CATALYST_THESIS`；
  market、persistence、data quality 永遠不計入 sustained-stop 門檻。
- 同日 `P3 RECOMMEND + P4 CAUTION` 合法並分開顯示；
  `P3 RECOMMEND + P4 STOP` 保存兩邊結果並回報 `TRACKING_SELECTION_CONFLICT`。
- STOPPED 股票未來仍可依既有「未命中交易日 >= 5」規則建立新 episode；舊 episode 不覆寫。
- Snapshot/Review 分別記錄 `v7_tracking` 與 `p4_state_v1`，並保存 family/stage/SHA metadata。

有效交易日即使 P3 候選為 0，P4 仍會完成所有 active observations 的檢查；只有整天沒有
交易資料才走 no-data。Point-in-time replay 由推薦日起按交易日順序重建，不寫 production
tables，也不使用未來資訊或 outcome 調整 production threshold。

### 23.5 `/signals/outcomes`：Day10 結果分析

篩選器支援日期、Prompt Family、Outcome Label、P3 Decision，以及 selection、
momentum score、research、assessment、global selector、reason、tracking prompt、
tracking state machine 等版本。明細採 backend pagination，CSV 採 streaming export。

核心卡片與圖表：

| 區塊 | 顯示內容 |
|---|---|
| 平均漏斗 | 每日 Phase 2 Eligible / Global Eligible / Recommended |
| Acceptable Rate | `(Winner + Neutral) / matured`，目標 80% |
| Winner > Neutral | Winner 與 Neutral 數量／比例 |
| Big Loser / Winner Recall | 正式推薦 Big Loser rate、global winners 被推薦的 recall、漏選 Winner、compression rate |
| Outcome 分布圖 | 成熟 RECOMMEND 的 Winner／Neutral／Big Loser |
| 每日趨勢圖 | Phase 2、Global、RECOMMEND、NOT_SELECTED、REMOVE、Technical Failure |
| Backend Rank | RECOMMEND、NOT_SELECTED、Winner 的 rank buckets；Rank Override 與其 Big Loser 數 |
| NOT_SELECTED Winner | 漏選 Winner 總數、rate、依 reason code 分布，可一鍵套 filter |
| Observation Outcome | Caution recovery、premature stop candidate、stop before big loss、平均停止交易日、停止後新 episode |

Outcome 明細欄位：

```text
日期 / 股票 / asset / P3 decision / backend+recommendation ranks
/ reason or theme / P4 status / Day10 return / Outcome label / versions
```

Day10 唯一定義為「推薦日收盤 → 第 10 個後續全市場交易日收盤」：

| 狀態 | 條件 | 是否進成熟分母 |
|---|---|---:|
| `WINNER` | return >= +10% | 是 |
| `NEUTRAL` | -10% < return < +10% | 是 |
| `BIG_LOSER` | return <= -10% | 是 |
| `IMMATURE` | 尚未走滿 10 個後續交易日 | 否 |
| `OUTCOME_DATA_MISSING` | entry/exit 必要價缺漏 | 否 |

只有 P3 正式 `RECOMMEND` 會進推薦 outcome；pre-P3 的歷史 `WATCH` 不會被事後改稱
RECOMMEND。Global selection failed 的日期不建立 global-eligible rows，因此也不會污染
Winner Recall 分母。

人工檢查清單會列出未入選後成 Winner、前段 rank 漏選 Winner、正式推薦 Big Loser、
Rank Override Big Loser、可能過早 STOP、資料缺漏等案例。人工操作只切換
`UNREVIEWED/REVIEWED` 與 note，不會修改 outcome label、P3 decision 或 source snapshot。

## 24. Legacy fallback 規則

只有以下情況會真正輸出 legacy：

- `SIGNALS_PIPELINE_MODE=legacy`
- `SIGNALS_PIPELINE_MODE=phase2_shadow`
- `phase2` 模式當次 Phase 2 發生 exception

Legacy 流程：

```text
raw pool
→ classification 三選一
→ legacy hard exclusions
→ deterministic priority ordering（不截斷）
→ soft hints
→ deterministic signals
→ legacy regime gate
→ LLM
```

### 24.1 Legacy classification

- LEADER：六條件全滿足，包括 sector RS>=70、peer RS>=80、score>=70、
  法人確認、volume>=1.3、距 20d high>=-3%。
- FOLLOWER：同 sector 有 leader、55<=score<70、5d 漲幅較 leader 低、
  RS 改善、flow3d>0、無爆量長上影。
- ROTATION_LAGGARD：同 sector 有 leader、sector 強、落後產業 20d return 至少
  5pp、RS 改善、法人/量能轉強、站回 MA10 或創高、score>=50。
- 三者都不符直接刪除。

### 24.2 Legacy hard exclusions

1. 人工黑名單（ETF / 金融不是 legacy hard exclusion）
2. flow5d<0 且非 rotation laggard
3. price3d>15%
4. avg turnover5d<5,000萬
5. 當日張數級距不合格
6. failed follow-through
7. price10d>25% 且 flow1d<0
8. flow3d>0、flow1d<0、price1d<-1.5%
9. market RS<40 且 RS rank change<=0

### 24.3 Legacy processing order

Legacy 在 soft/regime gate **之前**排序，但所有候選保留：

```text
LEADER → FOLLOWER → ROTATION_LAGGARD → other
→ in_top_stocks bonus
→ in_top_industries bonus
→ flow3d DESC
→ flow1d DESC
→ price5d DESC
→ stock_id
```

### 24.4 Legacy regime gate

- BROAD_BULL：score<50 刪除。
- NARROW_BULL：
  - leader 且 score>=65；或
  - score>=70 且無 distribution。
- VOLATILE_RANGE：刪 distribution、急拉、score<60、RS change<=-50、
  low conviction；但 tracked 且 max positive>=3%、max negative>-6% 可保留。
- RISK_OFF：只留 legacy leader、hit>=3、flow5d>0、無 distribution、market RS>=90。

| 結果分析 | 舊 archive Day10 使用 Day2 baseline，且沒有 P3 全體 outcome | P6 `day10_v1` 使用推薦日收盤到第 10 個後續交易日收盤 | `/signals/outcomes` 顯示一致的 Winner/Neutral/Big Loser |
| Outcome 回饋 | 無明確隔離 | 嚴格單向 `decision → analytics`，人工 note 也不改決策 | UI 可分析與標記，但不能自動調 prompt/gate |
| UI | 首頁單一 DailySignalsPanel + archive | 五頁產品 IA：總覽、正式推薦、觀察、結果、Debug | 可分別看今日決策、episode 與事後品質 |
